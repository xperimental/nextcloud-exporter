## Минимум про Go, чтобы читать дальше

Если вы уже знаете Go, пропустите этот раздел.

**Функция и возврат нескольких значений.** В Go функция может вернуть несколько значений
сразу. Это основной способ сообщать об ошибке:

```go
func parseVersion(raw string) (version, bool)
```

Возвращает разобранную версию и признак успеха. Вызов выглядит так:

```go
parsed, ok := parseVersion("34.0.1")   // := объявляет новые переменные
if !ok { ... }                         // ! это "не"
```

**Ошибка — обычное значение.** Тип `error` — это значение, которое либо `nil` (ошибки
нет), либо содержит описание проблемы. Проверка ошибки после каждого вызова — норма:

```go
if err := c.refresh(ctx); err != nil {
    // что-то пошло не так
}
```

**Срез (slice).** Список переменной длины, аналог массива. Записывается `[]T`, где `T` —
тип элементов. `[]int` — список чисел, `[]advisory` — список записей. `append(a, b)`
добавляет элементы и возвращает новый список. `len(a)` — длина.

**Структура (struct).** Набор именованных полей, аналог класса без методов:

```go
type advisoryPackage struct {
    Ecosystem string
    Name      string
}
```

**Указатель.** `*T` — «адрес значения типа `T`». Указатель может быть `nil`, то есть
«ничего». Это используется, чтобы отличать «значения нет» от «значение пустое»:
`*string` в поле `WithdrawnAt` равен `nil`, когда в ответе сервера это поле отсутствует.

**Метод.** Функция, привязанная к типу. Получатель пишется до имени:

```go
func (c *SecurityChecker) Check(...)   // метод типа *SecurityChecker
```

Внутри метода `c` — это тот объект, у которого метод вызвали.

**Экспорт по регистру.** Имя с большой буквы (`SecurityChecker`, `Check`) видно из других
пакетов, с маленькой (`refresh`, `parseVersion`) — только внутри своего пакета. Поэтому
внутренние детали здесь названы с маленькой буквы.

**Горутина.** `go f()` запускает функцию параллельно и сразу идёт дальше. Это то, что
позволяет обновлять список уязвимостей в фоне, не задерживая ответ на запрос метрик.

**Мьютекс.** Замок. Если два потока одновременно читают и пишут одну переменную, программа
может испортить данные. `mu.Lock()` захватывает замок, `mu.Unlock()` отпускает.
`RWMutex` умеет отдельно пускать читателей (`RLock`) — их может быть много одновременно —
и писателя (`Lock`), который работает в одиночку.

**`defer`.** Отложенный вызов: выполнится при выходе из функции, каким бы способом выход
ни произошёл. Используется, чтобы гарантированно освободить ресурс.

**Теги полей.** Строка в обратных кавычках после поля говорит, как поле называется в JSON:

```go
GHSAID string `json:"ghsa_id"`
```

Всё, что есть в JSON, но не описано в структуре, при разборе просто отбрасывается.

## `internal/metrics/security.go`

### Откуда берутся данные и почему именно оттуда

```go
advisoriesURL = "https://api.github.com/repos/nextcloud/security-advisories/security-advisories" +
    "?per_page=100&sort=published&direction=asc"
```

Это список уязвимостей, опубликованных проектом Nextcloud. Он единственный пригодный:

- Глобальная база уязвимостей GitHub и OSV.dev по Nextcloud **пусты** — Nextcloud
  публикует записи под собственным обозначением, которое GitHub не переносит в общую базу.
- Release notes использовать **нельзя**: правки безопасности мержатся из закрытых форков и
  в changelog не попадают вовсе. Проверено на конкретном примере — релизы, закрывшие
  CVE-2026-61527, не упоминают ни номер CVE, ни само исправление.

`per_page=100` — максимум записей на страницу. `sort=published&direction=asc` — сортировка
по дате публикации по возрастанию, и это важно: страницы отдаются курсором, а не номером.
При такой сортировке новые записи дописываются в конец, и уже отданные страницы не
сдвигаются. При сортировке по дате изменения запись, отредактированная в середине обхода,
может оказаться пропущенной.

### Числа, определяющие поведение

```go
advisoriesRefreshInterval = 12 * time.Hour
advisoriesRetryInterval   = 15 * time.Minute
advisoriesMaxAge          = 48 * time.Hour
advisoriesHTTPTimeout     = 30 * time.Second
advisoriesMaxPages        = 10
```

- **12 часов** — период обновления списка. GitHub без токена разрешает 60 запросов в час с
  одного адреса. Полная выкачка — три запроса, значит шесть запросов в сутки. Токен не
  нужен.
- **15 минут** — пауза перед повтором после неудачи. Даже при постоянных неудачах это
  четыре запроса в час, лимит не расходуется.
- **48 часов** — срок годности списка. Список уязвимостей только пополняется, поэтому
  опасность устаревших данных в том, что в них не будет свежей записи и метрика покажет
  ноль при реально нужном обновлении безопасности. Это худшее из возможных поведений,
  поэтому просроченный список перестаёт использоваться. 48 часов — это четыре пропущенных
  цикла обновления.
- **30 секунд** — таймаут одного запроса к GitHub. Это отдельная величина, не связанная с
  `--timeout`: тот задаёт ожидание Nextcloud внутри запроса метрик и измеряется секундами,
  а здесь запрос идёт в фоне.
- **10 страниц** — предохранитель от бесконечного обхода. Сейчас страниц три.

### Тип версии

```go
type version []int
```

Версия как список чисел: `"34.0.2.1"` превращается в `[34, 0, 2, 1]`.

Отдельный тип нужен потому, что версии приходят с разным числом компонентов. Nextcloud
сообщает свою версию **четырьмя** числами (`34.0.2.1`), а список уязвимостей указывает
исправленные версии **тремя** (`34.0.1`). Сравнивать их как строки нельзя: `"34.0.10"`
меньше `"34.0.9"` в алфавитном порядке, хотя по смыслу больше.

### Структуры под ответ сервера

```go
type advisory struct {
    GHSAID          string                  `json:"ghsa_id"`
    WithdrawnAt     *string                 `json:"withdrawn_at"`
    Vulnerabilities []advisoryVulnerability `json:"vulnerabilities"`
}
```

Одна запись об уязвимости. В ответе сервера полей гораздо больше, но описаны только нужные —
остальные при разборе отбрасываются.

`WithdrawnAt` — указатель (`*string`), а не строка, чтобы отличить «поля нет» (`nil`) от
заполненного значения. Заполненное означает, что запись отозвана и её надо игнорировать.
Обычная строка этого различия не даёт: и отсутствующее поле, и пустое дали бы `""`.

```go
type advisoryVulnerability struct {
    Package                advisoryPackage `json:"package"`
    VulnerableVersionRange string          `json:"vulnerable_version_range"`
    PatchedVersions        string          `json:"patched_versions"`
}
```

Сведения об одном затронутом продукте. `PatchedVersions` — версии, в которых уязвимость
исправлена. Это **строка, заполняемая людьми вручную**, и это главная сложность всей задачи
(см. ниже про `parsePatchedVersions`).

### Разобранный результат

```go
type advisoryFix struct {
    ghsaID          string
    patchedVersions []version
}

type advisorySnapshot struct {
    fixes     []advisoryFix
    fetchedAt time.Time
}
```

`advisoryFix` — итог разбора одной записи: идентификатор и список версий, где уязвимость
закрыта. Разбор делается **один раз при выкачке**, а не при каждом запросе метрик.

`advisorySnapshot` — снимок, результат одной успешной выкачки, вместе с временем.
Неизменяемый: следующая выкачка создаёт новый снимок и заменяет указатель на него.
Благодаря этому читателю достаточно скопировать указатель под замком, а дальше работать
без замка — данные, на которые он смотрит, никто не поменяет.

### Сам объект

```go
type SecurityChecker struct {
    log       logrus.FieldLogger
    userAgent string
    client    *http.Client
    url       string

    mu       sync.RWMutex
    snapshot *advisorySnapshot
}
```

`mu` защищает `snapshot`. Взят `RWMutex`, а не обычный `Mutex`, потому что читателей много
(каждый запрос метрик) и они друг другу не мешают, а писатель один и появляется раз в 12
часов.

`url` отдельным полем, а не константой напрямую, чтобы тесты могли подставить локальный
сервер вместо GitHub.

```go
client: &http.Client{
    Timeout: advisoriesHTTPTimeout,
},
```

Свой HTTP-клиент. Поле `Transport` намеренно не задано — используется стандартное, то есть
**проверка TLS-сертификата включена**. Это важно: флаг `--tls-skip-verify` относится к
серверу Nextcloud пользователя (у которого может быть самоподписанный сертификат) и на
GitHub распространяться не должен. Отдельный клиент это гарантирует на уровне структуры
кода, а не договорённости.

### Запуск фонового обновления

```go
func (c *SecurityChecker) Start(ctx context.Context) {
    go c.refreshLoop(ctx)
}
```

`go` запускает `refreshLoop` параллельно, `Start` сразу возвращает управление. Поэтому
**запрос метрик никогда не ждёт GitHub** — он читает готовый снимок.

Это ключевое архитектурное решение. Альтернатива — ходить в GitHub прямо во время запроса
метрик, когда кэш истёк, — означала бы, что раз в 12 часов один запрос платит три
последовательных запроса к GitHub. При стандартном `scrape_timeout` в 10 секунд это может
не уложиться, и тогда **упадёт весь запрос**, включая `nextcloud_up` и все остальные
метрики Nextcloud. То есть основная функция экспортёра стала бы зависеть от доступности
GitHub. Так делать нельзя.

Пока первая выкачка не закончилась, снимка нет, `Check` отвечает «не знаю», и метрика
ведёт себя как до появления проверки.

`ctx` (контекст) — стандартный способ сообщить «прекращай работу». Экспортёр не имеет
процедуры корректного завершения, поэтому на практике горутина живёт до конца процесса,
но контекст нужен для HTTP-запросов и делает поведение предсказуемым в тестах.

### Цикл обновления

```go
func (c *SecurityChecker) refreshLoop(ctx context.Context) {
    for {
        wait := advisoriesRefreshInterval
        if err := c.refresh(ctx); err != nil {
            c.log.Warnf("Security check: can not refresh advisories: %s", err)
            wait = advisoriesRetryInterval
        }

        timer := time.NewTimer(wait)

        select {
        case <-timer.C:
        case <-ctx.Done():
            timer.Stop()
            return
        }
    }
}
```

`for { }` без условия — бесконечный цикл. Каждый проход: обновить список, потом подождать.
Пауза зависит от результата: удалось — 12 часов, не удалось — 15 минут.

`select` — ожидание того из нескольких событий, которое произойдёт раньше. Здесь их два:
сработал таймер или отменили контекст. `<-timer.C` означает «дождаться значения из
канала». Без `select` отмена не сработала бы до конца паузы, и процесс не смог бы
завершиться быстро — пришлось бы ждать до 12 часов.

Обратите внимание: первая выкачка происходит **сразу**, до первой паузы, а не через 12
часов после старта.

### Обновление снимка

```go
func (c *SecurityChecker) refresh(ctx context.Context) error {
    advisories, err := c.fetchAll(ctx)
    if err != nil {
        return err
    }

    fixes := parseFixes(advisories)
    if len(fixes) == 0 {
        return fmt.Errorf("no usable advisories in %d records", len(advisories))
    }

    c.mu.Lock()
    c.snapshot = &advisorySnapshot{fixes: fixes, fetchedAt: time.Now()}
    c.mu.Unlock()

    c.log.Infof("Security check: loaded %d advisories for Nextcloud Server.", len(fixes))

    return nil
}
```

Три шага: выкачать, разобрать, заменить снимок.

Проверка `len(fixes) == 0` — защита от молчаливой поломки. Ноль пригодных записей означает,
что данные пришли, но ни одна не относится к Nextcloud Server. Так выглядело бы, например,
переименование обозначения продукта на стороне GitHub. Считать это «уязвимостей нет»
нельзя — метрика молча спрятала бы все обновления безопасности. Поэтому такой результат
объявляется ошибкой: старый снимок сохраняется, а если его нет, проверка остаётся
неактивной и метрика ведёт себя как раньше.

Замок держится только на время замены указателя — две строки, без сетевых операций внутри.

Ошибка на любом шаге означает, что снимок **не** заменяется. Предыдущий, пусть и не
свежий, лучше отсутствующего.

### Ответ на вопрос

```go
func (c *SecurityChecker) Check(current, available string) (hasSecurityFixes bool, ok bool) {
    c.mu.RLock()
    snapshot := c.snapshot
    c.mu.RUnlock()
```

`current` — установленная версия, `available` — доступная. Второе возвращаемое значение,
`ok`, — признак того, что ответ вообще получен. Если `ok` равен `false`, ответа нет, и
вызывающий обязан сообщить об обновлении, как делал до появления проверки.

Под замком выполняется только копирование указателя. Дальше замок не нужен: снимок
неизменяем.

```go
    if snapshot == nil {
        return false, false
    }

    if time.Since(snapshot.fetchedAt) > advisoriesMaxAge {
        c.log.Warnf("Security check: advisories are older than %s, reporting update.", advisoriesMaxAge)
        return false, false
    }

    currentVersion, currentOK := parseVersion(current)
    availableVersion, availableOK := parseVersion(available)
    if !currentOK || !availableOK {
        c.log.Warnf("Security check: can not parse versions %q and %q, reporting update.", current, available)
        return false, false
    }
```

Три причины ответить «не знаю»: снимка нет (первая выкачка не закончилась или все попытки
провалились), снимок просрочен, версии не разобрались. Во всех случаях второе значение —
`false`, и метрика останется единицей.

```go
    for _, fix := range snapshot.fixes {
        if isSecurityRelevant(fix, currentVersion, availableVersion) {
            c.log.Infof("Security check: update %s -> %s contains fix for %s.", current, available, fix.ghsaID)
            return true, true
        }
    }

    c.log.Infof("Security check: update %s -> %s contains no known security fixes.", current, available)

    return false, true
}
```

Перебор записей до первого совпадения. `for _, fix := range ...` — обход списка, где `_`
означает «индекс не нужен». Найденная запись пишется в лог, чтобы в проде было видно, из-за
какой именно уязвимости метрика поднялась.

### Главное: два правила сопоставления

```go
func isSecurityRelevant(fix advisoryFix, current, available version) bool {
    var highestOnCurrentBranch version
    for _, patched := range fix.patchedVersions {
        if patched.major() != current.major() {
            continue
        }

        if highestOnCurrentBranch == nil || compareVersions(patched, highestOnCurrentBranch) > 0 {
            highestOnCurrentBranch = patched
        }
    }

    // Правило первое.
    if highestOnCurrentBranch != nil && compareVersions(highestOnCurrentBranch, current) <= 0 {
        return false
    }

    // Правило второе.
    for _, patched := range fix.patchedVersions {
        if compareVersions(current, patched) < 0 && compareVersions(patched, available) <= 0 {
            return true
        }
    }

    return false
}
```

Одна запись об уязвимости перечисляет версии, в которых она исправлена, — по одной на каждую
поддерживаемую ветку. Например `32.0.12, 33.0.6, 34.0.1`.

**Правило первое: если на нашей ветке исправление уже установлено, запись нас не касается.**
Сначала находится самая большая из перечисленных версий нашей ветки, потом она сравнивается
с установленной.

Почему именно самая большая, а не любая: если запись перечисляет `31.0.1` и `31.0.7`, а
установлена `31.0.3`, то по `31.0.1` мы выглядим исправленными, хотя нужного `31.0.7` у нас
нет. Проверка «есть ли хоть какая-то версия не больше нашей» пропустила бы уязвимость.

**Правило второе: иначе уязвимость будет закрыта, если какая-то из исправленных версий
больше установленной и не больше доступной.** То есть исправление лежит между тем, что у
нас есть, и тем, куда мы обновляемся.

Вместе правила дают верный ответ и при переходе между ветками:

| установлено | доступно | исправлено в | результат | почему |
|---|---|---|---|---|
| 32.0.5 | 32.0.14 | 32.0.12, 33.0.6 | **да** | правило 2: `32.0.5 < 32.0.12 <= 32.0.14` |
| 32.0.12 | 32.0.14 | 32.0.12, 33.0.6 | нет | правило 1: исправление уже установлено |
| **32.0.14** | **33.0.6** | 32.0.12, 33.0.6 | **нет** | правило 1 гасит запись, хотя правило 2 сработало бы |
| 32.0.10 | 33.0.6 | 32.0.12, 33.0.6 | да | на нашей ветке исправления нет, придёт с новой веткой |
| 34.0.1 | 34.0.3 | 32.0.12, 33.0.6 | нет | все версии ниже установленной, правило 2 молчит |

Третья строка — та, ради которой существует правило первое. Установлена `32.0.14`, доступна
`33.0.6`. Правило второе само по себе сочло бы обновление нужным: `33.0.6` больше `32.0.14`
и не больше доступной. Но исправление `32.0.12` у нас уже есть, значит уязвимость закрыта.
Без правила первого любой, кто в порядке на старой ветке, получал бы ложное срабатывание
на каждом запросе метрик, постоянно.

Пятая строка показывает, что правило второе тоже не лишнее: правило первое там не
срабатывает, потому что версий нашей ветки в записи нет вовсе.

### Разбор записей

```go
func parseFixes(advisories []advisory) []advisoryFix {
    var result []advisoryFix

    for _, item := range advisories {
        if item.WithdrawnAt != nil {
            continue
        }

        var patched []version
        for _, vulnerability := range item.Vulnerabilities {
            if !isNextcloudServer(vulnerability.Package) {
                continue
            }

            patched = append(patched, parsePatchedVersions(vulnerability)...)
        }

        if len(patched) == 0 {
            continue
        }

        result = append(result, advisoryFix{ghsaID: item.GHSAID, patchedVersions: patched})
    }

    return result
}
```

Отбрасывается: отозванное (`WithdrawnAt != nil`), не относящееся к Nextcloud Server, и то,
из чего не удалось получить ни одной версии.

`append(patched, ...списком...)` с тремя точками на конце — добавление всех элементов
другого списка, а не самого списка одним элементом.

### Отбор нужного продукта

```go
var nextcloudServerNames = map[string]bool{
    "server":           true,
    "nextcloud server": true,
    "nextcloud/server": true,
    "nextcloud":        true,
}
```

`map[string]bool` — словарь, здесь используется как множество допустимых значений.

Сверяться со списком, а не искать подстроку `"Server"`, важно. В том же репозитории
публикуются уязвимости остальных продуктов Nextcloud — Talk, Desktop, Deck, Tables, — и их
номера версий пересекаются с серверными: у Talk бывает версия 18, когда у сервера 30.
Свободный поиск затащил бы в сравнение чужие версии и дал ложные срабатывания.

```go
func isNextcloudServer(pkg advisoryPackage) bool {
    if !strings.EqualFold(strings.TrimSpace(pkg.Ecosystem), "nextcloud") {
        return false
    }

    return nextcloudServerNames[strings.ToLower(strings.TrimSpace(pkg.Name))]
}
```

`TrimSpace` убирает пробелы по краям, `EqualFold` сравнивает без учёта регистра — в
реальных данных встречается и `nextcloud`, и `Nextcloud`.

Точное сравнение обозначения с `"nextcloud"` отсекает платную редакцию, которая
публикуется как `nextcloud enterprise` (а в части записей — с опечаткой
`nextcloud entreprise`). Её версии состоят из четырёх чисел вида `31.0.14.5`, которым не
соответствует ни один публичный релиз, поэтому для бесплатной редакции они бесполезны.

### Самое неприятное место: разбор версий из свободного текста

```go
func parsePatchedVersions(vulnerability advisoryVulnerability) []version {
    if versions := parseVersionList(vulnerability.PatchedVersions); len(versions) > 0 {
        return versions
    }

    return parseVersionList(vulnerability.VulnerableVersionRange)
}
```

Поле с исправленными версиями заполняется людьми и приходит в разном виде. Реальные
примеры из данных:

| Значение | Особенность |
|---|---|
| `"32.0.12, 33.0.6, 34.0.1"` | обычный случай |
| `">=32.0.0, >=33.0.0"` | неравенства вместо версий, нет пробела после знака |
| `" >= 29.0.0, >= 30.0.0"` | пробел в начале строки |
| `"31.0.1"` | одна версия без запятых |
| `">= 28.0.0, >= 29.0.0"`, а версии `"28.0.13, 29.0.10"` в другом поле | **поля перепутаны местами** |

Последний случай реален, это CVE-2025-47791. Отсюда запасной путь: если из поля с
исправленными версиями не удалось получить ни одной, пробуем поле с диапазоном. Такие
записи распознаются сами собой, потому что нормальный диапазон почти всегда содержит знак
неравенства и из него ничего не разберётся. На исправных записях запасной путь не
срабатывает: первое условие выполняется, и функция выходит раньше.

```go
func parseVersionList(raw string) []version {
    var result []version

    for _, token := range strings.Split(raw, ",") {
        token = strings.TrimSpace(token)

        if token == "" || strings.ContainsAny(token, "<>=~^") {
            continue
        }

        if parsed, ok := parseVersion(token); ok {
            result = append(result, parsed)
        }
    }

    return result
}
```

Разбиваем по запятой, чистим пробелы, отбрасываем всё, что версией не является.
`ContainsAny` проверяет наличие любого из перечисленных символов — так отсеиваются границы
диапазонов вроде `>= 32.0.0`. Всё, что осталось и не разобралось как число, тоже
отбрасывается молча: данные заполняются вручную, и падать на неожидаемом мусоре здесь
неправильно.

```go
func parseVersion(raw string) (version, bool) {
    raw = strings.TrimSpace(raw)
    if raw == "" {
        return nil, false
    }

    parts := strings.Split(raw, ".")
    result := make(version, 0, len(parts))
    for _, part := range parts {
        number, err := strconv.Atoi(part)
        if err != nil || number < 0 {
            return nil, false
        }

        result = append(result, number)
    }

    return result, true
}
```

`"34.0.2.1"` → `[34, 0, 2, 1]`. `strconv.Atoi` превращает строку в число; если не получилось
— вся строка версией не является. `make(version, 0, len(parts))` создаёт пустой список с
заранее выделенным местом под нужное число элементов — мелкая оптимизация, чтобы `append`
не перевыделял память.

### Сравнение версий

```go
func compareVersions(a, b version) int {
    length := len(a)
    if len(b) > length {
        length = len(b)
    }

    for i := 0; i < length; i++ {
        left, right := 0, 0
        if i < len(a) {
            left = a[i]
        }
        if i < len(b) {
            right = b[i]
        }

        if left < right {
            return -1
        }
        if left > right {
            return 1
        }
    }

    return 0
}
```

Идём по компонентам слева направо. Первое различие определяет ответ: `-1` если первая
меньше, `1` если больше, `0` если равны.

Ключевая деталь — **отсутствующие компоненты считаются нулём**. Цикл идёт до длины более
длинной версии, а у короткой недостающие позиции подставляются как `0`. Поэтому:

- `34.0.1` и `34.0.1.0` — **равны**;
- `34.0.2.1` **больше** `34.0.2`.

Именно это позволяет сравнивать четырёхкомпонентную версию Nextcloud с трёхкомпонентной из
списка уязвимостей, не приводя их к одному виду заранее.

Стандартной библиотеки для этого не взято сознательно: `21.0.3.1` не является корректной
версией по правилам semver, и библиотека semver отвергла бы собственные версии Nextcloud.

### Выкачка страниц

```go
func (c *SecurityChecker) fetchAll(ctx context.Context) ([]advisory, error) {
    var result []advisory

    next := c.url
    for page := 0; next != ""; page++ {
        if page >= advisoriesMaxPages {
            return nil, fmt.Errorf("too many pages, stopped after %d", advisoriesMaxPages)
        }

        advisories, link, err := c.fetchPage(ctx, next)
        if err != nil {
            return nil, err
        }

        result = append(result, advisories...)
        next = link
    }

    return result, nil
}
```

Цикл идёт, пока сервер сообщает адрес следующей страницы. Пустая строка означает, что
страница была последней.

Ошибка на любой странице прекращает обход и **возвращает `nil`, а не то, что успели
собрать**. Это принципиально: неполный список выглядел бы как «уязвимостей нет» и мог бы
скрыть обновление безопасности.

```go
func (c *SecurityChecker) fetchPage(ctx context.Context, pageURL string) ([]advisory, string, error) {
    req, err := http.NewRequestWithContext(ctx, http.MethodGet, pageURL, nil)
    if err != nil {
        return nil, "", err
    }
    req.Header.Set("Accept", "application/vnd.github+json")
    req.Header.Set("X-GitHub-Api-Version", "2022-11-28")
    req.Header.Set("User-Agent", c.userAgent)

    res, err := c.client.Do(req)
    if err != nil {
        return nil, "", err
    }
    defer res.Body.Close()
```

Заголовки — то, что GitHub просит присылать: формат ответа и версия API. `User-Agent` — тот
же, что экспортёр посылает Nextcloud, вида `nextcloud-exporter/0.9.1`.

`defer res.Body.Close()` — закрытие тела ответа при выходе из функции любым путём. Без этого
соединение не вернётся в пул и утечёт. `defer` здесь стоит **до** проверок ниже, поэтому
закрытие произойдёт и при ошибке разбора.

```go
    if res.StatusCode != http.StatusOK {
        return nil, "", fmt.Errorf("unexpected status code %d (rate limit remaining: %q)",
            res.StatusCode, res.Header.Get("X-RateLimit-Remaining"))
    }
```

Любой ответ кроме 200 — ошибка. Исчерпание лимита GitHub выглядит как 403 или 429, но
отдельной обработки не требует: следующая попытка будет через 15 минут. Остаток лимита
попадает в текст ошибки, чтобы причину было видно в логе — иначе `403` без пояснений
выглядит как проблема с правами.

```go
    var advisories []advisory
    if err := json.NewDecoder(res.Body).Decode(&advisories); err != nil {
        return nil, "", fmt.Errorf("can not parse advisories: %w", err)
    }

    return advisories, nextPageURL(pageURL, res.Header.Get("Link")), nil
}
```

`Decode(&advisories)` разбирает JSON в структуры. `&` передаёт адрес переменной, чтобы
функция могла её заполнить. `%w` в тексте ошибки сохраняет исходную ошибку внутри новой —
так вызывающий может при необходимости узнать первопричину.

GitHub отдаёт адрес следующей страницы в заголовке `Link`:

Функция ищет среди ссылок ту, что помечена `rel="next"`, и возвращает её адрес.

Сверяются **только схема и хост**. Путь сверять нельзя: как видно из примера выше, GitHub

Это неочевидное место, поэтому оно закрыто отдельным тестом — `TestNextPageURL` проверяет

## `internal/metrics/collector.go`

Здесь принимается решение о значении метрики.

```go
if systemInfo.Update.Available && systemInfo.Version != systemInfo.Update.AvailableVersion {
    updateAvailableValue = 1.0

    if security != nil {
        if hasFixes, ok := security.Check(systemInfo.Version, systemInfo.Update.AvailableVersion); ok && !hasFixes {
            updateAvailableValue = 0.0
        }
    }
}
```

Внешнее условие — исходная логика экспортёра, она не менялась. Внутри добавлены четыре
строки.

`security != nil` — проверка, включена ли опция. Когда она выключена, в коллектор передан
`nil`, и весь блок пропускается: поведение точно такое, как до изменений.

Условие `ok && !hasFixes` — и есть гарантия безопасного поведения. Значение опускается до
нуля только когда одновременно **получен ответ** (`ok`) и **исправлений нет** (`!hasFixes`).
Любая неопределённость — нет данных, GitHub недоступен, версии не разобрались — оставляет
единицу. Это выражено одним условием, а не рассыпано по нескольким ветвям, поэтому ошибиться
в нём трудно.

Метки метрики (`version`, `available_version`) не меняются ни на одном пути, поэтому
существующее правило алерта продолжает работать без правок.

`SecurityChecker` передаётся в `RegisterCollector` пятым аргументом и может быть `nil` —
в этом пакете принято передавать зависимости значениями, а не через интерфейсы.

## `internal/config/config.go`

Опция добавлена в пяти местах — так же, как устроены остальные опции экспортёра:

1. константа переменной окружения `NEXTCLOUD_INFO_UPDATE_SECURITY`;
2. поле `UpdateSecurity` в структуре `InfoConfig` с тегом `yaml:"updateSecurity"` — под
   этим именем опция читается из файла конфигурации;
3. регистрация флага `--enable-info-update-security`;
4. чтение переменной окружения;
5. слияние слоёв конфигурации в `mergeConfig`.

Плюс правило проверки:

```go
if c.Info.UpdateSecurity && !c.Info.Update {
    return errValidateSecurityNeedsUpdate
}
```

Проверка бессмысленна без метрики обновлений, поэтому такая комбинация — явная ошибка при
старте. Автоматически включать метрику обновлений было бы хуже: она заставляет Nextcloud
делать дополнительную работу, о которой не просили.

Порядок слоёв в этом экспортёре неочевиден и стоит запомнить: **переменные окружения
перекрывают файл конфигурации, а файл перекрывает флаги командной строки**. Кроме того,
`mergeConfig` перекрывает только ненулевыми значениями, поэтому включённую в нижнем слое
опцию нельзя выключить в верхнем. Это существующее поведение, новая опция просто ему
следует.

## `main.go`

```go
var securityChecker *metrics.SecurityChecker
if cfg.Info.UpdateSecurity {
    securityChecker = metrics.NewSecurityChecker(log, userAgent)
    securityChecker.Start(context.Background())

    log.Info("Security update check enabled: only updates containing security fixes are reported.")
}
```

`var securityChecker *metrics.SecurityChecker` объявляет указатель со значением `nil`. Если
опция выключена, он таким и остаётся, и коллектор получает `nil` — то есть ни одной
горутины, ни одного запроса к GitHub, никаких изменений в поведении.

`context.Background()` — пустой контекст, который никогда не отменяется. Экспортёр
завершается через `log.Fatal`, процедуры корректного завершения у него нет, поэтому
горутина живёт до конца процесса.

Строка в лог важна практически: она сообщает администратору, что смысл метрики изменился.
Иначе ноль в метрике при доступном обновлении выглядел бы как поломка.

## Как это выглядит в работе

Старт с включённой опцией:

```plain
Nextcloud server: http://nextcloud Authentication using token.
Security update check enabled: only updates containing security fixes are reported.
Listen on :9205...
Security check: loaded 106 advisories for Nextcloud Server.
```

Дальше на каждый запрос метрик одна строка с решением:

```plain
Security check: update 34.0.0.12 -> 34.0.3.2 contains fix for GHSA-99gw-ww6p-f2rr.
Security check: update 34.0.2.1 -> 34.0.3.2 contains no known security fixes.
```

Если GitHub недоступен:

```plain
Security check: can not refresh advisories: Get "https://api.github.com/...": dial tcp: connection refused
```

и метрика остаётся единицей.

Расход запросов к GitHub: три при старте, потом три каждые 12 часов. Лимит без токена — 60
в час на адрес.

## Что стоит знать про ограничения

- **Проверка склонна перестраховываться.** Записи об уязвимостях содержат и диапазоны
  затронутых версий, но в реальных данных эти поля ненадёжны — встречается разное число
  элементов в связанных полях, из-за чего сопоставить их по позиции невозможно. Поэтому
  диапазоны не вычисляются, и обновление может быть помечено как несущее исправление, даже
  если установленная версия никогда не была уязвима. Ошибка в эту сторону безопасна: она
  означает «вам предложат обновиться», то есть поведение без проверки.
- **Сигнал об обычных обновлениях теряется.** При включённой опции не остаётся метрики,
  сообщающей о неохранных обновлениях. Если нужны оба сигнала, запускайте второй экземпляр
  экспортёра без этой опции.
- **Метрика перестаёт быть чистой функцией ответа Nextcloud** и начинает зависеть от
  доступности GitHub. Безопасное поведение при отказе ограничивает последствия, но отказ
  виден только в логе — отдельных метрик состояния источника нет.
